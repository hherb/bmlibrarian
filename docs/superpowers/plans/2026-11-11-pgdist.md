# pgdist (bundled PostgreSQL 18 + pgvector + pg_search) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `bml setup` installs a private PostgreSQL 18 with pgvector (and pg_search where it exists) from our own pinned, checksummed release, so `--pg-bindir` is no longer needed.

**Architecture:** A committed inputs file pins three upstream sources. One bash script, run by a manually triggered CI workflow on five runners, verifies them, builds pgvector, extracts pg_search, prunes LLVM/Python and packs one tarball per target. The workflow smoke-tests each tarball with the existing ignored integration tests plus one new one, then publishes them as a GitHub Release. At run time a new `bml_setup::pgdist` module downloads the matching tarball (bmlib `download_verified`), unpacks it atomically into `<config>/pgdist/<version>/`, and the Database step initialises the private server from it.

**Tech Stack:** Rust (workspace `rust/`, MSRV 1.89), bmlib `model-download` + `http-ureq`, serde, bash + jq in GitHub Actions, system `tar`.

**Spec:** `docs/superpowers/specs/2026-11-11-installer-walking-skeleton-design.md` (Goal A; piece 1). Background: `docs/superpowers/specs/2026-11-07-one-click-installer-design.md`.

## Global Constraints

- PostgreSQL **18.6** from `theseus-rs/postgresql-binaries` release **`18.6.1`**; pgvector **`v0.8.7`** built from source (pinned by commit); pg_search **`0.26.6`** from ParadeDB release `v0.26.6`.
- pgdist version string: **`18.6-r1`**; release tag **`pgdist-18.6-r1`**; asset name **`bml-pgdist-18.6-r1-<target>.tar.gz`**.
- Targets: `aarch64-apple-darwin` (pg_search), `x86_64-apple-darwin` (no pg_search), `x86_64-pc-windows-msvc` (no pg_search), `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (pg_search, from the `bookworm` `.deb`).
- pg_search sources: macOS `pg_search-pg18-0.26.6.pkg`; Linux `postgresql-18-pg-search_0.26.6-1PARADEDB-bookworm_{amd64,arm64}.deb`.
- Every downloaded input is checked against a committed sha256; theseus tarballs also pass `gh attestation verify --repo theseus-rs/postgresql-binaries`.
- Pruned from the bundle: `libLLVM*`, `llvmjit*`, the bundled Python runtime, every `*plpython*` file. The server runs with `jit = off`.
- Licence and dependency notices are kept (theseus `LICENSE`, `COPYRIGHT`, `dependency-notices/`; pgvector `LICENSE`; pg_search `LICENSE` + a `SOURCE.txt` linking `https://github.com/paradedb/paradedb/tree/v0.26.6`).
- Installed location: `<config dir>/pgdist/18.6-r1/` (system disk, versioned, side by side). The Python app's `~/.bmlibrarian/.env` and `config.json` are never read or written.
- `--pg-bindir` and `--existing-server` keep working unchanged. A saved private or existing server is always resumed in preference to the bundle.
- Golden rules apply in Rust: named constants, no hard-coded paths outside constants, all errors reported in plain language, docstrings (`missing_docs` is on), pure functions where possible.
- Gate: `cd rust && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` stays green on every task; the Python suite (`uv run python -m pytest tests/`) stays green before the PR.

## Review Focus

1. **Interrupted install:** a kill during extraction leaves `pgdist/.18.6-r1.partial`. The next run removes it and installs again; it never treats a half-unpacked folder as installed (Task 3 test `leftover_partial_is_replaced`).
2. **Earlier `--pg-bindir` setup on this machine** (the owner's Postgres.app): `bml setup` with no flags resumes the saved server and downloads nothing (Task 4 test `bundled_plan_resumes_saved_private_server`).
3. **No asset for this computer** (Windows arm64, musl Linux, or before the release is pinned): the Database step fails with a message naming `--pg-bindir`, and independent steps still run (Task 4 test `bundled_plan_without_asset_fails_plainly`).
4. **Wrong archive:** a tarball whose `pgdist.json` names another version or target is refused and nothing is installed (Task 3 test `mismatched_archive_is_refused`).
5. **Two setups at once** (CLI and, later, the app): the second fails clearly on the download lock and does not unpack over the first (Task 3 test `install_refuses_while_another_setup_downloads`).

### Task 2: pgdist inputs, build script and release workflow

**Files:**
- Create: `rust/pgdist/inputs.json`, `rust/pgdist/build.sh`, `.github/workflows/pgdist.yml`

**Interfaces:**
- Produces: for each target, `rust/pgdist/out/bml-pgdist-18.6-r1-<target>.tar.gz` and a `.sha256` beside it. The tarball's single root folder `bml-pgdist-18.6-r1-<target>/` contains:
  - `pgdist.json`: `{"schema_version":1,"version":"18.6-r1","target":"<target>","inputs":{…copied from inputs.json for this target…},"pg_search":<bool>,"files":[{"path":"…","size":N,"sha256":"…"}]}`, listing every other file, paths relative to the root with `/` separators
  - `pg/`: the pruned theseus tree, with the bin folder at `pg/bin`
  - `ext/lib/postgresql/`: `vector.{dylib|so|dll}`, plus `pg_search.*` where present
  - `ext/share/postgresql/extension/`: `vector.control`, `vector--*.sql`, plus `pg_search.control` and `pg_search--*.sql` where present
  - `notices/`

  (`ext/` uses `bml-pgserver`'s existing extension-folder layout, `lib/postgresql` + `share/postgresql`, so no `bml-pgserver` change is needed.)

- [ ] **Step 1: Write `inputs.json`** with the pinned values. Fetch them, never guess:
  - theseus: `gh release download -R theseus-rs/postgresql-binaries 18.6.1 -p 'postgresql-18.6.1-<target>.tar.gz.sha256'` for each of the 5 targets. Record `url` and `sha256`.
  - pgvector: `gh api repos/pgvector/pgvector/git/ref/tags/v0.8.7`. Record `tag` and the commit `sha` (dereference an annotated tag).
  - ParadeDB: `gh release view -R paradedb/paradedb v0.26.6 --json assets --jq '.assets[]|select(.name=="<asset>")|.digest'` for the 3 assets. Record `url` and `sha256`. Targets without pg_search have `"pg_search": null`.
- [ ] **Step 2: Write `build.sh <target>`** (`set -euo pipefail`; runs on macOS, Linux and Git Bash on Windows; needs `curl`, `jq`, `tar`, `gh`, and `make` or `nmake`). In order:
  1. Read the target's entry from `inputs.json`; unknown target → exit 1.
  2. Download each input to `out/work/`. Verify sha256 with a `sha256_of()` helper (`sha256sum` or `shasum -a 256`). Run `gh attestation verify <theseus tarball> --repo theseus-rs/postgresql-binaries`.
  3. Unpack theseus into `<root>/pg`.
  4. Prune: `find <root>/pg \( -name 'libLLVM*' -o -name 'llvmjit*' -o -name '*plpython*' -o -name 'libpython*' \) -exec rm -rf {} +` and `rm -rf <root>/pg/lib/Python <root>/pg/lib/bitcode`. On macOS, fail if `otool -L` on any remaining Mach-O in `pg/bin` and `pg/lib` names a removed library. On Linux, do the same with `ldd` ("not found").
  5. pgvector: `git clone --depth 1 --branch v0.8.7`, then check that `git rev-parse HEAD` equals the pinned commit.
     - macOS/Linux: `make PG_CONFIG=<root>/pg/bin/pg_config with_llvm=no`. The `with_llvm=no` matters: theseus was configured `--with-llvm` against a Homebrew clang path the runner may not have.
     - Windows: `PGROOT=<root>/pg nmake /F Makefile.win`.
     - Copy the library and the `.control`/`sql/vector--*.sql` files into `ext/`.
  6. pg_search, when present:
     - macOS: `pkgutil --expand-full <pkg> work/pkg`, then copy `*/Payload/lib/postgresql/pg_search.dylib` and `*/Payload/share/postgresql/extension/pg_search*`.
     - Linux: `dpkg-deb -x <deb> work/deb`, then copy `usr/lib/postgresql/18/lib/pg_search.so` and `usr/share/postgresql/18/extension/pg_search*`.
     - Neither runs package scripts.
  7. Copy the notices; write `notices/pg_search/SOURCE.txt` when pg_search is present.
  8. Write `pgdist.json` with `jq`, including the per-file sha256 list.
  9. `tar -czf out/bml-pgdist-18.6-r1-<target>.tar.gz -C out <root-name>`, then write its `.sha256`.

### Task 3: `bml_setup::pgdist`: release metadata, host target, atomic install

**Files:**

**Interfaces:**
- Consumes: `crate::lock_downloads`, `crate::sweep_stale_parts`, `crate::SetupError`, `bmlib::embed::download_verified(url, file, size, sha256, dir, progress)`.
- Produces:
  ```rust
  pub const PGDIST_DIR_NAME: &str = "pgdist";          // under the config dir
  pub const PGDIST_MANIFEST_FILE: &str = "pgdist.json";
  pub const PGDIST_BIN_SUBDIR: &str = "pg/bin";
  pub const PGDIST_EXT_SUBDIR: &str = "ext";
  #[derive(Deserialize)] pub struct PgdistAsset { pub file: String, pub size: u64, pub sha256: String }
  #[derive(Deserialize)] pub struct PgdistRelease { pub version: String, pub base_url: String, pub assets: BTreeMap<String, PgdistAsset> }
  pub fn bundled_release() -> Result<PgdistRelease, SetupError>;   // parses include_str!("../pgdist-release.json")
  pub fn host_target() -> Option<&'static str>;                    // cfg!-based, one of the 5 targets
  pub struct InstalledPgdist { pub root: PathBuf }
  impl InstalledPgdist { pub fn bindir(&self) -> PathBuf; pub fn extension_dir(&self) -> PathBuf; }
  pub fn install_from_archive(archive: &Path, pgdist_dir: &Path, version: &str, target: &str) -> Result<InstalledPgdist, SetupError>;
  pub fn installed(pgdist_dir: &Path, version: &str, target: &str) -> Result<Option<InstalledPgdist>, SetupError>;
  pub fn ensure_pgdist(config_dir: &Path, release: &PgdistRelease, target: &str, progress: &mut dyn FnMut(u64, u64)) -> Result<(InstalledPgdist, bool /* newly installed */), SetupError>;
  ```

- [ ] **Step 1: Write `pgdist-release.json`** as `{"version":"18.6-r1","base_url":"https://github.com/hherb/bmlibrarian/releases/download/pgdist-18.6-r1/","assets":{}}`. The assets stay empty until Task 5.
- [ ] **Step 2: Write the failing tests** in `pgdist.rs`. Test archives are built with the system `tar` from a temp tree whose root folder holds a `pgdist.json` with the given version and target, plus `pg/bin/marker`.
  - `bundled_release_parses`: `bundled_release().unwrap().version == "18.6-r1"`.
  - `installs_atomically`: `install_from_archive` returns a root of `<pgdist_dir>/18.6-r1`; `bindir()` ends with `pg/bin` and contains `marker`; no `.18.6-r1.partial` is left behind; `installed(..)` is then `Some`.
  - `already_installed_is_found`: a second `installed` call returns `Some` without touching the archive (delete the archive first).
  - `leftover_partial_is_replaced`: with a stale `.18.6-r1.partial/junk` present, the install succeeds and `junk` is gone.
  - `mismatched_archive_is_refused`: an archive whose manifest says target `x86_64-pc-windows-msvc` → `Err`, whose message names both targets, and neither `18.6-r1` nor the partial folder exists afterwards.
  - `archive_without_manifest_is_refused`: → `Err`, and nothing is installed.
  - `install_refuses_while_another_setup_downloads`: hold `lock_downloads(config_dir)`, then `ensure_pgdist` with an asset → `Err` mentioning another setup, and no `pgdist/18.6-r1`.
- [ ] **Step 3: Run them.** `cargo test -p bml-setup pgdist`. Expected: FAIL (module missing).
- [ ] **Step 4: Implement:**
  - `install_from_archive`:
    1. Remove `<pgdist_dir>/.<version>.partial` if present and create it empty.
    2. Run `tar -xzf <archive> -C <partial>`; on a spawn failure, say that the system `tar` is needed.
    3. Require exactly one top-level folder containing `pgdist.json` whose `version` and `target` match.
    4. Rename that folder to `<pgdist_dir>/<version>` and remove the partial.

    Every failure removes the partial and returns `SetupError::Other` with a plain-language message. Add the comment `// shortcut: per-file sha256s in pgdist.json are not re-checked here (the archive's sha256 already was); check them when piece 5 copies a bundled folder instead`.
  - `installed`: `Some` when `<pgdist_dir>/<version>/pgdist.json` parses with the matching version and target.
  - `ensure_pgdist`, in order:
    1. Return `installed(..)` if present.
    2. Take the download lock and check `installed(..)` again.
    3. Look the asset up by target.
    4. `sweep_stale_parts` the downloads folder.
    5. Call `download_verified(base_url + file, file, size, sha256, <pgdist_dir>/downloads, …)`.
    6. Call `install_from_archive`, then delete the downloaded archive.
  - `host_target`: `cfg!(target_os, target_arch)` pairs map to the 5 targets; anything else is `None`.
- [ ] **Step 5: Run the tests and the gate.** `cargo test -p bml-setup && cargo clippy --all-targets -- -D warnings`. Expected: PASS.
