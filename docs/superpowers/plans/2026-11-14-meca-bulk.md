# MECA Bulk Full Text (Installer Piece 3c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a user who enters their own AWS keys and chooses "All of medRxiv"
gets the backlog's full text from medRxiv's MECA bulk archive
(`s3://medrxiv-src-monthly`, requester pays) instead of one paper every
30 s. Each package's JATS XML and PDF go into the same `documents/` cache
and `publication_fulltext` rows as the paper-by-paper route, so the index
phase needs no change. Progress is checkpointed per package. After the
archive, the paper-by-paper route fills the gap since the newest package.

**Architecture:** two halves.

1. **bmlib (Python + Rust, shared fixtures; owner rule: bmlib additions land
   in both).** `bmlib.fulltext.meca` / `bmlib::fulltext::meca`:
   - `sigv4`: AWS Signature Version 4 for S3 GET requests, pure (the caller
     passes the time). Held to AWS's published S3 examples.
   - `s3`: ListObjectsV2 and S3 error replies parsed (pure), and the
     transport: list a prefix page by page, download one object to a file
     (streamed, size and single-part ETag checked, published atomically).
     Requester pays on every request.
   - `package`: read one `.meca` ZIP (manifest, JATS, PDF), refusing unsafe
     members. **Waits for Task M0**: no real package has been seen yet.
2. **BMLibrarian (`rust/bml-library`, `bml-db`, `bml-cli`).** A bulk phase
   that lists the archive once into a checkpoint table, then per package:
   download, read, match the JATS DOI and version to a `publications` row,
   save JATS/PDF into the cache, update `publication_fulltext`, delete the
   package file. AWS keys stored owner-only in the config dir.

**Tech Stack:** Python ≥3.11 stdlib (`hmac`, `hashlib`, `xml.etree`,
`zipfile`) plus `httpx` for the transport (new extra `meca`). Rust: bmlib's
existing `sha2`, `md-5`, `roxmltree`, `ureq`; new `hmac` 0.12 (and `zip`
for Task B4), behind a new feature `meca`.

**Spec:** `docs/superpowers/specs/2026-11-11-installer-walking-skeleton-design.md`
(Goal C, "Two routes"; piece 3c).

## Owner decisions (2026-11-14)

- This session: this plan, then the bmlib part (Tasks B1–B3; B4 after M0),
  as a bmlib PR. The bulk route in `bml-library` is a later session.
- Small paid requester-pays requests with the owner's `medrxiv` AWS profile

  the existing `sha2`; Python stdlib), not `aws-sdk-s3` or boto3.

## Made by Claude (open to correction)

- One module per language under `fulltext/` (MECA is full text); S3 code
  stays inside it until a second user of S3 exists.
- Credentials are an access key id, a secret and an optional session token.
  Their `repr` / `Debug` never shows the secret or the token.
- Only what the route needs: GET (object, listing), no PUT, no multipart
  upload, no presigned URLs, no regions other than the bucket's.
- A download is refused, not truncated, when the bytes received differ from
  the listed size, or when a single-part ETag (no `-`) differs from the MD5
  of the bytes. A multipart ETag is not checked (it is not an MD5).

### Task B1: SigV4 signing (pure) — done 2026-11-14 (bmlib PR #775)

- [x] `bmlib/fulltext/meca/sigv4.py` / `rust/bmlib/src/fulltext/meca/sigv4.rs`:
      `S3Credentials`, `sign_get(method, host, path, query, headers,
      credentials, region, now) -> headers` (adds `x-amz-date`,
      `x-amz-content-sha256` = SHA-256 of the empty body,
      `x-amz-security-token` when present, `Authorization`). URI encoding as
      S3 wants it (each path segment encoded, `/` kept; query keys and
      values encoded and sorted). Header names lower-cased, values trimmed
      and inner spaces collapsed.
- [x] Contract `tests/fixtures/s3_sigv4.json`: AWS's published S3 examples
      (GET object with `Range`, ListObjects `?max-keys=2&prefix=J`, keys
      `AKIAIOSFODNN7EXAMPLE`, 2013-05-24) with their documented canonical
      request, string to sign and signature, plus a requester-pays listing
      and a key with characters that need encoding. Python and Rust both
      assert every case.

### Task B2: S3 replies (pure) — done 2026-11-14

- [x] `parse_list_objects_v2(xml) -> ListPage` (objects: key, size, ETag
      without quotes, last modified; `is_truncated`;
      `next_continuation_token`). A truncated page without a token, a size
      that is not a non-negative integer, or a missing key is refused
      (`S3Error::Malformed`), never skipped.
- [x] `classify_error(status, body) -> S3Error` from S3's `<Error><Code>`:
      `AccessDenied`, `InvalidAccessKeyId`, `SignatureDoesNotMatch`,
      `RequestTimeTooSkewed`, `ExpiredToken`, `NoSuchKey`, `NoSuchBucket`,
      `SlowDown` / `ServiceUnavailable` / `InternalError` / a bare 500 or 503
      (`RetryLater`), anything else kept with its code and message. Each has
      a plain-language `reason()` for the wizard, the same sentence in both
      languages (the fixture holds them); none echoes a key.
- [x] Contract `tests/fixtures/s3_responses.json` (bodies in the shapes S3's
      API reference documents).

### Task B3: transport — done 2026-11-14

- [x] Python: `list_objects(client, credentials, bucket, region, prefix,
      continuation_token)` and `download_object(client, credentials, bucket,
      region, key, destination, expected_size, etag)` over an
      `httpx.Client` the caller passes in; the download streams to a temp
      file beside the destination, checks size and ETag, then `os.replace`s
      (bmlib's atomic-publish rule; tested by hooking `os.replace`).
- [x] Rust: the same over `HttpClient`. `HttpResponse` holds the whole body
      in memory and a package can be large, so `HttpClient` gains
      `get_with_headers_stream` (an `HttpStream`; the default refuses, like
      the other optional methods). `UreqClient` streams with no body-size or
      whole-body limit, only `timeout_per_read` (ureq ≥ 3.5, an idle limit
      like httpx's read timeout), so a large package is cut off only for
      stalling.
- [x] Tests with fake clients: signed headers present, requester-pays
      header sent, pagination followed, an error reply classified, a short
      body or wrong ETag refused and no file left behind.

- Review (PR #775) added: no redirects (a redirect would carry the session
  token), UTF-8-only replies, keys with `.`/`..` segments refused (httpx
  rewrites them after signing), Rust's `Unsupported` kind for a client that
  cannot stream. Known divergence: ureq decodes a gzip-encoded body, so Rust
  fails such an object on size where Python refuses it (`shortcut:` in
  `s3.rs`); recheck in M0.

## BMLibrarian tasks (later session)

### Task L1: pin and checkpoint table

- [ ] Pin bmlib past B4, feature `meca`. bml-db migration 3:
      `meca_packages` (key PK, size, etag, last_modified, state
      `listed|done|unmatched|failed`, doi, version, error, attempts,
      updated_at).

### Task L2: AWS keys

- [ ] `bml library aws-keys set` (key id on the command line or stdin,
      secret from stdin only) writes `bml-aws.json` with mode 600 in the
      config dir; `clear` deletes it. Never logged; `status` says only
      whether keys are present.

### Task L3: bulk phase

- [ ] Runs before paper-by-paper full text when keys are present and the
      bulk listing is not done; metadata first, so DOIs can match.
- [ ] Lists the archive once into `meca_packages` (resumable by the last
      key), prints the count, size and cost estimate, then works through
      `listed` rows: download to `<library>/.meca-tmp/`, read, match DOI +
      version, save through `FullTextCache`, update `publication_fulltext`
      in one transaction with the row's `done`, delete the package.
      A package whose DOI is not in `publications` yet is `unmatched` and
      retried after the next metadata sync. An older version than the
      stored one is `done` without replacing anything.
- [ ] `AccessDenied` / bad keys stop the phase with the plain-language
      reason and the paper-by-paper route continues (exit 0 if that
      completes; the reason is shown in `status`).

### Task L4: CLI and status

- [ ] `bml library update` runs the bulk phase when keys exist (`--skip
      bulk` to leave it out). `status` shows packages done / unmatched /
      failed / left and bytes downloaded.

## Review Focus

- Secrets: no key or token in a log line, error message, `Debug` or test
  snapshot.
- A refused download leaves no partial file under the destination name.
- `S3Error::Malformed` never silently drops an object from a listing (a
  missing package is a missing paper).
- Python and Rust agree on every contract case.
