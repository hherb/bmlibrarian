# `bml-setup` + `bml setup` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One headless command, `bml setup`, checks every BMLibrarian
requirement and installs only what is missing:
- the database: the private PostgreSQL, or an existing usable PostgreSQL 18
- the private server's login autostart
- Ollama
- the two approved generation models
- the pinned embedding GGUF

Re-running it resumes or repairs.

**Architecture:**
- A UI-free `bml-setup` library crate runs a fixed list of idempotent
  steps. Each step checks first, acts only when needed, and reports progress
  through a callback, so piece 4's Tauri screen can drive the same code.
- The logic is pure, unit-tested functions: host parsing, model-name
  matching, pull-stream parsing, hardware verdicts, step skipping and
  existing-server verdicts.
- Thin I/O wrappers sit on top: bmlib's `HttpClient` for Ollama's HTTP API,
  bmlib's verified download for the GGUF and the Ollama installers, and
  `bml-pgserver` for the database.
- The existing-server path ("adopt") lives in `bml-pgserver`, next to the
  private server, because it shares role, database and extension creation.

**Tech Stack:** Rust (workspace in `rust/`, edition 2021, `rust-version =
"1.85"`), `bml-pgserver`, `bmlib` (git dependency pinned by rev until 0.3.1
is published; `default-features = false, features = ["http-ureq",
"model-download"]`), `sysinfo` 0.35 (add feature `disk`), `serde_json` 1,
`clap` 4.5, `tempfile` 3 (dev). No new crates beyond these.

**Spec:** `docs/superpowers/specs/2026-11-07-one-click-installer-design.md`
(piece of work 3). **This is plan 2 of the installer.** Prior: plan 1
`2026-11-07-rust-pgserver.md` (landed: PRs #396, #400). Later: obtaining
pinned PG18/pgvector/pg_search binaries (its own plan; owner decision
2026-11-07), the Tauri first-run screen, packaging.

## Owner decisions (2026-11-07, this plan)

- The GGUF download is reused from bmlib through a new llama-free
  `model-download` feature (Task 1), not through `embed`.
- Portable PostgreSQL binaries are **not** in this plan: `bml setup` takes
  `--pg-bindir` / `--extension-dir` like `bml server init`.
- The existing-PostgreSQL path **is** in this plan.
- `medgemma4B_it_q8:latest` is not in Ollama's registry (404) and is built
  locally. Setup pulls **`medgemma1.5:4b-it-q8_0`** and copies it to
  **`medgemma4B_it_q8:latest`**.

## Global Constraints

- **Never read or write the Python app's `~/.bmlibrarian/.env` or
  `config.json`.** Rust-stack files only: `bml.env`, `bml-admin.env`,
  `bml-pgserver.json`, the new `bml-external.json`, `models/` and
  `downloads/`. They live in the config folder: `--config-dir`, else
  `BML_CONFIG_DIR`, else `~/.bmlibrarian`.
- **Never change a pre-existing PostgreSQL** beyond creating the new role
  `bml_app`, the database `bmlibrarian` and its extensions. Refuse when
  `bml_app` or `bmlibrarian` already exist and are not ours. Never edit
  `shared_preload_libraries`. Never read user tables. The only
  connections allowed are:
  - to the maintenance database `postgres`, for cluster catalogs and
    `CREATE ROLE`/`CREATE DATABASE`
  - to `bmlibrarian`
- An existing server counts as usable when **all** of these hold:
  - major version ≥ **18**
  - the supplied role is a superuser
  - `vector` is available, version ≥ **0.8.1**
  - on macOS and Linux only: `pg_search` is available **and** listed in
    `shared_preload_libraries`
- An existing server's host must be loopback: `127.0.0.1`, `::1` or
  `localhost`. The connection has no TLS, so a superuser password never
  crosses a network.
- **Passwords never appear in argv.** The existing server's superuser
  password comes from `BML_PG_SUPERUSER_PASSWORD`, or from one stdin line
  with `--password-stdin`.
- Approved models, exactly (never substituted; low RAM or disk only warns):

  | Ollama name (must exist after setup) | pulled as |
  |---|---|
  | `gpt-oss:20b` | `gpt-oss:20b` |
  | `medgemma4B_it_q8:latest` | `medgemma1.5:4b-it-q8_0`, then `/api/copy` |

- Embedding model: `bmlib::embed::ARCTIC_EMBED_L_V2_F16`, stored in
  `<config_dir>/models/`.
- Ollama default host: `http://127.0.0.1:11434`. Ollama is installed or
  started **only** when the host is loopback. A remote host that does not
  respond is a failed step, never an install.
- Ollama release pinned to **v0.40.10** (published 2026-10-23, more than
  two weeks old). Base URL:
  `https://github.com/ollama/ollama/releases/download/v0.40.10/`.

  | platform | asset | size | sha256 |
  |---|---|---|---|
  | macOS | `Ollama-darwin.zip` | 220350228 | `0c8ac7dc394a7b6171d8531bdaba60dd8dd2d8ed525ebc6c4526a91497a029ee` |
  | Windows | `OllamaSetup.exe` | 1661645848 | `051556bec8d51d65a5e81e46aa9c238fff4fff0d47ce164fb25203ae48ed1c99` |
  | Linux | `install.sh` | 15902 | `25f64b810b947145095956533e1bdf56eacea2673c55a7e586be4515fc882c9f` |

  Linux runs the pinned `install.sh` with `OLLAMA_VERSION=0.40.10`. The
  script itself downloads the versioned tarball, plus GPU add-ons, **without
  a checksum we can verify**. Document this gap; don't hide it. It uses
  `sudo` (accepted by the spec), and setup says so before it runs.
- Hardware warnings (warn and continue; named constants in
  `bml-setup/src/hardware.rs`):
  - total RAM < `MIN_RAM_BYTES = 16 * 1024³`
  - free space < the bytes still to download, where the free space is
    measured on the disk holding Ollama's model folder (`OLLAMA_MODELS`,
    else `~/.ollama/models`) and the disk holding `<config_dir>/models`
  - approximate sizes: `gpt-oss:20b` 13_800_000_000; `medgemma1.5:4b-it-q8_0`
    5_000_000_000; the GGUF uses its pinned `size`
  - The database folder is never presized (spec goal 5).
- Every public item has a doc comment (`missing_docs = "warn"`). Numbers,
  names and URLs are named constants. Every error a user sees says what
  happened and what to do next.
- Gate: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test` in `rust/`, plus `cargo test -- --include-ignored` against
  a real PG18 (`BML_TEST_PG_BINDIR`) for the database tasks. The Python suite
  must still pass (nothing Python changes).

## Review Focus

1. **Interrupted and repeated runs.** A run can be killed:
   - mid-pull
   - mid-GGUF
   - between saving `bml-external.json` and `CREATE ROLE`

   A re-run then finishes without duplicates or a "name taken" refusal of our
   own objects. A pull resumes from Ollama's partial blobs and the GGUF
   re-downloads from scratch (bmlib removes its `.part` file), so neither
   leaves a corrupt model. *(Task 2:
   `adopt_resumes_after_state_saved_before_objects`; Task 6:
   `setup_database_private_then_resume`,
   `setup_database_existing_then_resume`.)*
2. **`OLLAMA_HOST` spellings.** Each of these maps to a URL and a loopback
   flag; a remote host never triggers an install:
   - `0.0.0.0`, `127.0.0.1:11434`, `localhost`, `http://localhost:11434/`
   - `[::1]:11434`, `https://gpu-box:443`, an empty string

   *(Task 4: `parse_ollama_host_table`.)*
3. **A pull stream that fails part-way.** An `{"error": …}` line, or a body
   that ends without `{"status":"success"}`, is a failed step quoting
   Ollama's message, never "installed". *(Task 4:
   `pull_without_success_fails`, `pull_error_line_fails`.)*
4. **Free space for a path that doesn't exist yet**, or on an external
   volume (`/Volumes/Data/…`, `D:\…`), uses the nearest existing ancestor
   and the longest mount-point prefix. *(Task 3:
   `free_space_uses_longest_mount_prefix`.)*
5. **A superuser password with spaces, quotes, `#`, `=` or non-ASCII
   characters** round-trips through `bml-admin.env`. One with a line break
   or leading/trailing whitespace is refused with a plain message, before
   anything is written. *(Task 2: `storable_password_rules`,
   `env_roundtrips_awkward_password`.)*

    `SetupError` into `Failed(message)`.

    report: &mut dyn FnMut(StepEvent)) -> StepOutcome`: one step, for the

  - **Hardware:** `ram_warning` and `disk_warnings` for the models still
    missing (a listing failure → assume all are missing) and for the GGUF
    if it isn't there. Each warning is a `Warning` event; the outcome is
    `AlreadyPresent` unless the step itself failed.
  - **Database:**
    - `Private` → `init`; `created ? Installed : AlreadyPresent`
    - `Existing` → `adopt`, mapped the same way
    - `None` → private state found → `init` with the saved paths; external

      `bml-admin.env` and rebuild the `ExternalRequest`; neither found →
      `Failed("no database chosen; pass --pg-bindir or --existing-server")`

    `AlreadyPresent` or `Installed`, based on a check before enabling.
    Decide how to check "already enabled" from `autostart.rs`'s
    per-platform paths; add `pub fn is_enabled() -> Result<bool,
    PgServerError>` there if missing.
  - **Ollama:** `ensure_ollama`.
  - **Models:** for each `APPROVED_MODELS` entry, run `model_action`, then
    pull and/or copy, forwarding pull progress as `Progress`. Re-list the
    models after each pull: the copy needs the pulled name.
  - **EmbeddingModel:** `download_model(&ARCTIC_EMBED_L_V2_F16,
    &config_dir.join(MODELS_DIR_NAME), …)`, with `MODELS_DIR_NAME =
